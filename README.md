## 为什么是「辅助」，而不是「自动刷分脚本」

市面上常见的《弗一把》脚本是**纯自动刷分**：挂机代打、无人值守连续提交、抢在对手之前疯狂猜。它们毁掉的是这个游戏最核心的乐趣——推理，也让其他玩家、让作者心寒。

本项目选择了完全不同的路线：

| | 本脚本（辅助） | 自动刷分脚本 |
| --- | --- | --- |
| 定位 | 计算与输入辅助 | 全自动代玩 |
| 提交 | 默认由你手动点击，可选自动 | 无人值守狂刷 |
| 公平性 | 每一步都是你的决定 | 机器抢跑，破坏公平 |
| 权限 | 只在页面上「打字」，与手动操作完全等价 | 常需读取/篡改页面逻辑甚至账号信息 |
| 服务器负担 | 一次对局几个请求 | 高频请求，污染战绩 |
| 透明性 | 全开源、无混淆、无隐藏行为 | 闭源灰产，随时可能夹带私货 |
| 风控风险 | 不触发任何服务端校验 | 高危，随时可能被限制 |

**它的本质是什么？** 游戏本身是「信息 + 推理」玩法：每轮反馈会逐步缩小目标选手的范围。本脚本做的事，就是替你算清楚「下一步猜谁，信息收益最大」——这和象棋引擎给棋手提供建议、词典帮你查生词是同一类工具。

**它不替你玩游戏**：

- 填入的每一个猜测，提交前你都能看到、修改、反悔；
- 自动提交是**可选**的（默认关闭），且只在多人联机生效，一样可以随时关掉；
- 它不碰内存、不改网络请求、不读取服务器协议，页面代码一行未动。

**为什么这样更好？** 自动刷分脚本是在透支游戏的寿命——用的人多了，作者失去维护动力，服务器被刷子拖垮，正常玩家离开。而辅助工具让新手也能享受推理的乐趣，并在「为什么这一步是最优」的思考中，真正学会这个游戏的玩法。赢，要赢得明白。

## 特性

- 🧠 **最优猜测求解器** — 信息熵（平均信息增益）与极小化极大（最坏情况最优）双策略，移植自《弗一把》官方仓库的 `scripts/solver.js`，与原游戏判定逻辑完全一致
- 🎮 **单人模式自动接管** — 开局后自动计算并填入每一轮的最优猜测，结算与战绩自动统计
- 🌐 **多人联机自动接管** — 匹配/建房对局自动接管；DOM 轮询解析反馈（不依赖 WebSocket）；自动检测本局/整场结束、停止填充等待下一局；重赛（rematch）自动续接
- ⚡ **可选自动提交**（多人）— 填入后自动点击提交，支持冷却重试与昵称一致性校验；默认关闭，一键开关
- 📊 **经验积累** — 本地记录各难度下被猜中的选手，用于候选排序，越玩越懂你的对手
- 📦 **选手库自动获取** — 默认从 GitHub 数据仓库（csgo-major-db）拉取选手数据；网络异常时回退本地导入 `players_full.json`；反馈数据自动回写修正本地属性
- 🎛 **全功能可开关** — 自动填入、自动提交均可通过油猴菜单随时切换

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)（或 Violentmonkey）；
2. 点击安装脚本：[friberg-helper.user.js](https://github.com/byJming/friberg-helper/raw/main/friberg-helper.user.js)，油猴会弹出安装确认，点击安装；
3. 刷新打开《弗一把》游戏页面，右下角出现「弗一把助手」面板即安装成功；
4. **首次使用**：无需手动操作，助手默认自动从 GitHub 数据仓库（csgo-major-db）获取选手库；网络不可用时，点面板「导入 JSON」选择本仓库 `data/players_full.json`（646 名选手）作为回退。
> ⚠️ **重要提示：跨源资源访问授权**
>
> 首次使用同步选手库时，油猴（Tampermonkey / Violentmonkey）会弹出「该脚本请求访问跨源资源」的确认框——这是因为脚本需要从 GitHub 的 csgo-major-db 数据仓库拉取选手数据，属于脚本的正常功能，请点击**「临时允许」（仅本次）或「始终允许」（推荐）**。
>
> 如果拒绝了授权，脚本将无法联网获取数据，**不影响其他功能**——点面板「导入 JSON」，选择本仓库自带的 `data/players_full.json` 即可离线使用。

> 建议从本仓库获取最新版本（脚本内置更新地址，油猴会自动提示更新），警惕来路不明的改版脚本。

## 使用

### 单人模式

- 开始一局后，助手自动接管：面板显示当前候选数量与推荐猜测，输入框自动填入；
- 点「提交猜测」完成本轮（`自动填入` 开启时）；
- 猜中 / 次数耗尽后，面板显示战绩与经验统计。

### 多人联机

- 匹配或建房进入对局后，助手自动接管；
- 默认只**填入**不提交（与单人一致，均为手动提交）：确认推荐后点「提交猜测」；
- 想要全自动，可在油猴菜单开启「切换自动提交」——填入、校验、提交、等待反馈循环自动进行；
- 本局/整场结束时自动停止接管并记录结果，下一局或重赛自动恢复。

### 油猴菜单

| 菜单项 | 作用 |
| --- | --- |
| 切换自动填入 | 开关「自动填入输入框」 |
| 切换自动提交 | 开关「多人自动点击提交」（默认关闭） |
| 导入本地 JSON 数据 | 导入选手库文件（推荐使用本仓库 `data/players_full.json`） |
| 清空积累经验 | 清空本地战绩与经验统计 |

## 工作原理

```
选手库 ──编码──> 索引(国籍/赛区/队伍/年龄/位置/Major冠军/Major次数/状态)
                        │
对局反馈 ──DOM/网络──> 反馈键(与官方判定一一对应)
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
  候选集过滤(缩小范围)          最优猜测(信息熵 / 极小化极大)
        │                               │
        └───────────┬───────────────────┘
                    ▼
            填入输入框(原生 setter + input 事件，等同手动输入)
                    │
                    ▼
        提交(手动或可选自动)
```

- **求解器**：对每个候选猜测计算它对当前候选集的期望信息量（熵），选择信息收益最大的；候选集较小时切换为极小化极大，保证最坏情况下的猜测次数最少。判定键使用官方同源公式，保证与服务器反馈完全一致。
- **多人解析**：每 2 秒轮询自己的计分板表格，按行的 CSS 状态（correct/close/箭头）还原服务器反馈并过滤候选集；通过「局数变化 / 行数清零 / 结算卡片」识别新局、整场结束与重赛。
- **与页面交互**：只读 DOM + 原生 value setter 触发 React 事件，与手动打字、手动点击完全等价；单人模式的网络监听仅用于**读取**官方接口响应（等价于你亲眼看到反馈），不改写任何请求。
- **数据安全**：所有战绩与经验仅保存在本机（油猴存储），不上传任何服务器；不收集任何账号信息。
